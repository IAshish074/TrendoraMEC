1. ARCHITECTURE OVERVIEW
===============================================================================

The backend is built as a production-grade microservices architecture using Java 17, 
Spring Boot 3.3.5, and Spring Cloud 2023.0.3.

Core Principles Followed:
- 8 Independent Spring Boot Applications + 1 Shared Common Library
- Single Entry Point: API Gateway (Port 8080) for all frontend communications (/api/*)
- Asymmetric RSA 2048-bit JWT Signing & Verification
- Strict Database Isolation per Service (No cross-database queries or shared entities)
- Asynchronous Event-Driven Architecture using RabbitMQ (Topic Exchange)
- Server-Side PayPal Payment Verification (No frontend payment trust)
- Embedded Asynchronous Email Consumers (No redundant Notification service)
- Flyway Database Migrations for versioned schema management
- Multi-stage Dockerfiles & Docker Compose orchestration

4. REST API ENDPOINTS & ROUTING
===============================================================================

All requests flow through Gateway at http://localhost:8080:

Auth Endpoints:
  POST   /api/auth/register          Register new user (default ROLE_USER)
  POST   /api/auth/login             Authenticate user & return RSA JWT + Refresh token
  POST   /api/auth/refresh           Obtain new access token using refresh token
  POST   /api/auth/logout            Revoke refresh token
  POST   /api/auth/forgot-password   Trigger password reset email token
  POST   /api/auth/reset-password    Reset password using valid token

User Profile Endpoints:
  GET    /api/users/profile          Get authenticated user profile
  PUT    /api/users/profile          Update authenticated user profile
  GET    /api/users/addresses        Get user addresses
  POST   /api/users/addresses        Add address
  DELETE /api/users/addresses/{id}   Delete address
  GET    /api/users                  List all users (Admin only)
  PUT    /api/users/{id}/role        Update user role (Admin only)
  DELETE /api/users/{id}             Delete user profile (Admin only)

Product Catalog Endpoints:
  GET    /api/products               List products with search & filters
  GET    /api/products/{id}          Get product by ID
  POST   /api/products               Create product (Admin only)
  PUT    /api/products/{id}          Update product (Admin only)
  DELETE /api/products/{id}          Delete product (Admin only)
  GET    /api/products/categories    List categories
  POST   /api/products/categories    Create category (Admin only)

Cart Endpoints:
  GET    /api/cart                   Get authenticated user's cart
  POST   /api/cart/items             Add item to cart
  PUT    /api/cart/items/{itemId}    Update item quantity
  DELETE /api/cart/items/{itemId}    Remove item from cart
  DELETE /api/cart                   Clear cart

Order Endpoints:
  POST   /api/orders                 Create order (with price snapshot)
  GET    /api/orders/my-orders       Get authenticated user's order history
  GET    /api/orders/{id}            Get order by ID (Owner or Admin)
  GET    /api/orders                 List all orders (Admin only)
  PUT    /api/orders/{id}/status     Update order status with transition validation (Admin)

Payment Endpoints:
  POST   /api/payments/create        Create payment order (returns PayPal Order ID)
  POST   /api/payments/verify        Server-side PayPal payment verification
  POST   /api/payments/refund        Process refund (Admin only)

Inventory Endpoints:
  GET    /api/inventory/{productId}  Get stock level for product
  POST   /api/inventory/adjust       Adjust stock level (Admin only)

6. SAGA WORKFLOWS
===============================================================================

Checkout & Stock Reservation Saga:
  Client -> Gateway -> Order Service (Create order status PENDING)
          -> Publish ORDER_CREATED
          -> RabbitMQ -> Inventory Service (Verify stock)
          -> If stock available: Reserve stock & Publish INVENTORY_RESERVED
          -> If stock insufficient: Publish INVENTORY_REJECTED
          -> Order Service receives event and updates status to PAYMENT_PENDING or CANCELLED.

Payment & Order Confirmation Saga:
  Client -> Gateway -> Payment Service -> PayPal API verification
          -> If verified: Update status to PAID & Publish PAYMENT_COMPLETED
          -> Order Service receives event: Updates status to CONFIRMED & Publishes ORDER_CONFIRMED
          -> OrderEmailConsumer receives ORDER_CONFIRMED & sends confirmation email asynchronously.

Compensating Workflow on Payment Failure:
  Payment verification fails -> Publish PAYMENT_FAILED -> Order Service cancels order
  -> Publish ORDER_CANCELLED -> Inventory Service releases reserved stock back to available quantity.
